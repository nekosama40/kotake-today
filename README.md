# こたけから、きょう。

小竹向原から約1時間以内で行ける、東京23区のイベントを約1か月分まとめるWebサイトです。予約不要・当日券・途中参加など、当日に参加しやすい催しを優先します。満席・受付終了は掲載せず、今日終了したイベントだけは「終了」を選んだ場合に確認できます。

オンライン版: <https://nekosama40.github.io/kotake-today/>

## サイトを開く

```powershell
npm install
npm run dev
```

表示された `http://127.0.0.1:5173` をブラウザで開きます。常用URLは `http://127.0.0.1:4173` です。本番用ファイルは次のコマンドで `dist/` に作成されます。

```powershell
npm run build
npm run serve
```

## 必要なときだけ1か月更新

更新はWindowsの毎朝タスクではなく、必要なときだけ手動で開始します。Luna（推論 `max`）が、更新日を含む31日間を次の6系統で並行調査します。

- 公式・自治体・施設・大手イベント
- 公開X・Instagram・地域・小規模イベント
- アニメ・キャラクター
- 食べ物・マルシェ
- IT・AI・ゲーム・コミュニティ
- 展示・音楽・ワークショップ・変わった企画

6系統の統合後、掲載候補が4件未満の日があれば追加の補完調査を行います。公式URL、開催日、会場、受付状況、小竹向原からの時間、乗り換え回数を検証し、画像を公式ページから取得・軽量化してから公開します。調査や検証に失敗した場合は、現在公開中のデータを保持します。

SNS調査では `config/research-sources.json` のマーク済みアカウントを参照します。X・Instagramのプロフィールだけで候補にせず、公開投稿から主催者・会場・出演者・出店者を辿り、公式ページやチケットページで確認します。Peatix、connpass、Doorkeeper、TwiPla、Meetup、TIGET、teket、ZAIKO、自治体、施設、商店街なども横断します。

今日から31日分を調査・検証・公開してGitHub Pagesへ送信:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\run-monthly-update.ps1
```

既存の月間下書きを再検証・公開するとき:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\run-monthly-update.ps1 -ReuseExistingDraft
```

サイトは公開済みの31日分から東京時間の「今日」を自動表示します。日付が変わってもAI調査は発生せず、保存済みデータ内で表示日だけが進みます。調査ログは `logs/`、調査結果と公開前データは `work/` に保存されます。

## 品質確認

```powershell
npm run check
```

テスト、イベントデータ検証、TypeScriptと本番ビルドをまとめて実行します。

## 掲載方針

- 東京23区内、更新日から31日分、小竹向原から概ね60分以内・乗り換え1回まで
- 予約不要・当日受付・当日券・途中参加を優先
- 公式、自治体、施設、イベントサービス、公開SNS、店舗、学校、地域団体、小規模コミュニティまで横断
- X・Instagramはマーク済みイベントまとめアカウント＋日付・地域・ジャンルの組み合わせ検索を使用
- 受付終了、満席、売り切れ、中止、延期、終了済みは除外
- 画像は公式告知ページの公開画像をローカルへ保存し、1000px以内のWebPへ軽量化。取得できない場合はサイト内のカテゴリー画像を表示
- eスポーツは独立タブにせず、ほかのジャンルと同じタグ・候補として扱う

オンライン版はGitHub Pagesで公開します。`dist/` は一般的な静的ホスティングにも配置できます。
